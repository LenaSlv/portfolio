# Частые баги вёрстки сайта

## Flex-элемент раздувает страницу на мобильном

Симптом: контент обрезан по краям экрана одинаково с обеих сторон (заголовок секции, соседние секции тоже задеты) — это не зум и не баг одного блока, а горизонтальный overflow всей страницы. Пользователь может настаивать, что зума нет и кэш ни при чём, — проверить сначала стоит именно вёрстку.

В этом проекте встречались две причины подряд (в разных секциях):

1. `.container` — flex-элемент родителя с `display:flex; flex-direction:column`, но у `.container` есть `margin: 0 auto` без явного `width`. Горизонтальные auto-margin отключают `align-items:stretch` по кросс-оси: контейнер вместо растягивания на всю ширину экрана садится по размеру содержимого и центрируется. Фикс — явный `width: 100%` на этом контейнере.
2. Дочерний элемент с `flex: 0 0 auto` (не сжимается) содержит картинку/контент шире мобильного viewport (например, `.screen-card` с картинкой 610px при экране 390px). `max-width: 100%` на `<img>` не спасает — сама карточка уже раздулась под контент раньше, чем сработало это ограничение. Фикс — на мобильном (`@media (max-width: 960px)`) переопределять на `flex: 1 1 100%; max-width: 100%; min-width: 0;`.

Как проверять, не имея живого телефона под рукой: headless Chrome через `playwright-core` + системный браузер (`C:/Program Files/Google/Chrome/Application/chrome.exe` как `executablePath`, ставить только `playwright-core`, не полный `playwright`, чтобы не тянуть загрузку движка). Сравнить `document.documentElement.scrollWidth` с `window.innerWidth` на viewport ~390×844 — если `scrollWidth` больше, где-то есть нешринкающийся элемент; список конкретных виновников — `document.querySelectorAll('body *')`, отфильтрованные по `el.scrollWidth > innerWidth`.

## Внешние интервалы между смысловыми блоками в адаптиве

Не путать внешний интервал между соседними секциями с внутренним `gap` контейнера. Если пользователь просит уменьшить расстояние «от обложки до контекста» или между смысловыми блоками, менять прежде всего `padding-bottom` предыдущей секции и `padding-top` следующей. Не уплотнять заодно расстояния между заголовком, текстом, карточками и макетами внутри секции.

Фактический внешний интервал обычно равен сумме нижнего и верхнего `padding`. Например, `20px + 20px` у соседних секций визуально дают `40px`, а не `20px`.

Для адаптивов всех страниц кейсов использовать единый ориентир, если отдельный макет не задаёт другое значение:

- до `640px`: `32px` от обложки до первого смыслового блока и `40px` между следующими смысловыми секциями;
- от `641px` до `960px`: около `52px` от обложки до первого блока и `56px` между секциями;
- переходы к блокам «Другие проекты» и «Контакты» уплотнять по тому же принципу.

Проверять не только CSS-значения, но и фактическое расстояние в браузере. На viewport `390×844` измерить разницу между `getBoundingClientRect().bottom` последнего видимого элемента предыдущего блока и `getBoundingClientRect().top` первого видимого элемента следующего блока. Для первого перехода считать от нижнего края обложки до строки-категории или заголовка следующего блока. Одновременно убедиться, что `document.documentElement.scrollWidth === window.innerWidth`.

Скриншот, вставленный в Figma как изображение, не обновляется после деплоя. При сверке адаптива проверять живую страницу и актуальную версию CSS, а не старую статичную картинку.

## Кнопка возврата наверх обязательна на каждой странице

При создании или пересборке любой страницы сайта и любого кейса добавлять фиксированную кнопку возврата наверх в правом нижнем углу. Использовать существующий компонент проекта, не создавать отдельную реализацию для каждой страницы:

```html
<button class="scroll-to-top" type="button" data-scroll-to-top aria-label="Наверх">
  <svg viewBox="0 0 24 24" aria-hidden="true"><path d="M12 19V5M6 11l6-6 6 6"/></svg>
</button>
```

Поведение и оформление брать из общих `.scroll-to-top` в `styles-site.css` и `[data-scroll-to-top]` в `site.js`: кнопка появляется после прокрутки страницы и возвращает пользователя к началу. При работе с существующей страницей проверять наличие компонента и добавлять его, если его нет.

Перед завершением проверять на полноразмерном и мобильном viewport, что кнопка находится в правом нижнем углу, не выходит за границы экрана, не создаёт горизонтальный overflow и по нажатию возвращает `scrollY` к `0`.

## styles-site.css и site.js обязаны иметь версию в ссылке

GitHub Pages отдаёт статику с `Cache-Control: max-age=600`. Если `<link href="styles-site.css">` / `<script src="site.js">` без query-параметра, браузер может держать старую версию до 10 минут после деплоя — обновление `?v=` в адресе самой HTML-страницы (`case-corporate.html?v=3`) не спасает, потому что CSS и JS — это отдельные закэшированные ресурсы со своим URL.

Правило: при любой правке `styles-site.css` или `site.js` бампить версию в ссылках на них сразу во всех HTML-файлах — `index.html`, `case-corporate.html`, `case-transport-pet.html`, `case-soul.html`, `case-arm-kassira.html` (`styles-site.css?v=N` → `?v=N+1`, синхронно для CSS и JS).
